## QA belongs next to your repo

qmax-code is the **QA terminal that can switch inference**. It brings tests,
crawls, review, healing, and Exposure Receipts into a terminal session, and
can host a coding agent when the work calls for one.

- **Pick your agent.** Use `/orch` to switch between Claude Code, Codex,
  Antigravity, and OpenCode, or the built-in Anthropic, Cerebras, and Ollama
  backends.
- **Start without a QualityMax account.** Standalone `--local` mode provides
  repository file and command tools. Bring an authenticated coding CLI or an
  inference backend; use a local Ollama endpoint to keep inference local too.
- **Connect for hosted QA.** QualityMax-connected mode adds project and test
  management, site crawls, test generation and execution, repository review,
  script healing, and live browser feeds.
- **Install one binary.** qmax-code is written in Go. Release downloads cover
  macOS, Linux, and Windows on Intel and ARM. The CLI itself needs no Node,
  npm, or Python runtime; hosted coding CLIs have their own requirements.

## What changes with this release

The CLI’s license is Apache 2.0 now. The source, README, contributor terms,
and release archives all reflect that change. Every platform archive includes
the license, copyright notice, and third-party dependency licenses.

This announcement applies to v1.38.0 and future releases. Older release
artifacts retain the license shipped with them. Third-party dependencies keep
their own licenses. The hosted QualityMax backend remains a separate,
closed-source service.

## Try it today

```bash
curl -sL https://qualitymax.io/static/install-qmax-code.txt | bash
qmax-code --local --backend codex
```

The example uses an already authenticated Codex CLI. You can also select
Claude Code with `--backend cc`, or run `qmax-code --local` with a configured
built-in inference backend.

For hosted QA workflows:

```bash
qmax-code login
qmax-code
# Inside the terminal: /orch
```
